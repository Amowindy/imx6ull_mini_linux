# 内核模块裁剪评估

> **最终决定（2026-11-07）**：已采用**无模块方案**，当前 defconfig 为
> `CONFIG_MODULES=n`，**生成 0 个 .ko**。以下 101 个 .ko 清单是裁剪前的
> 分析记录，已按建议删除/转为 built-in。
>
> 最终保留为 built-in 的功能：
> `USB ACM`、`USB Serial`、`FTDI_SIO`、`HW_RANDOM`/`IMX_RNGC`、
> `VLAN_8021Q`、`MSDOS_FS`、`BINFMT_MISC`、`LIBCRC32C`、
> `CAN`/`CAN_FLEXCAN`、`UART3`、`I2C2`、`KEYBOARD_GPIO`。
>
> 已移除：USB 4G/WWAN、USB 网卡、AF_ALG/KTLS、CAAM、MD/DM、
> RPMSG/SIOX、PS/2、测试模块、传统加密算法。
>
> 裁剪前统计：**101 个 .ko，合计约 2.5MiB**。
> 模块本身不大，但大量小模块会显著拉长增量编译/链接时间，并增加 rootfs 体积。

## 4. 建议方案

| 方案 | 模块数 | 模块体积 | 说明 |
|---|---:|---:|---|
| 当前 | 101 | ~2.5MiB | 默认 |
| 保守裁剪 | ~18 | ~0.7MiB | 保留第 1、2 类，删除测试/CAAM/冗余 |
| 激进裁剪 | ~7 | ~0.3MiB | 只保留第 1 类；USB 4G/WiFi/FAT16/AF_ALG 全部不编 |
| 无模块 | 0 | 0 | `CONFIG_MODULES=n`，把 USB 串口/RNG 改成 `=y` |

推荐先采用**保守裁剪**，确认 USB 串口、CAN、TF 卡、网络、RNG 正常后，再考虑“无模块”方案。

## 5. 操作方式（由你决定后执行）

可以用 `menuconfig` 逐项关闭，也可以先生成一份裁剪 fragment：

```text
# 示例：删除测试/CAAM/legacy crypto/MD-DM/RPMSG/SIOX
# CONFIG_USB_TEST is not set
# CONFIG_USB_EHSET_TEST_FIXTURE is not set
# CONFIG_DMATEST is not set
# CONFIG_CRYPTO_DEV_FSL_CAAM is not set
# CONFIG_CRYPTO_TCRYPT is not set
# CONFIG_MD is not set
# CONFIG_BLK_DEV_DM is not set
# CONFIG_RPMSG is not set
# CONFIG_SIOX is not set
...
```

然后：

```bash
./build.sh menuconfig      # 或直接编辑 defconfig
./build.sh savedefconfig
./build.sh build
```

> 不要只看 `=m` 数量：关闭父选项后，很多子模块会自动消失；
> 建议每次裁剪后执行 `make savedefconfig`，再 `grep '=m$' .config` 复核。

## 6. 决策记录（已执行）

| 项目 | 决定 |
|---|---|
| USB 4G/WWAN | 不需要，删除 `option`/`usb_wwan` |
| USB 有线网卡 | 不需要，删除 `pegasus`/`rtl8150`/`cdc_eem` |
| VLAN | **需要**，`VLAN_8021Q=y` built-in |
| FAT16 | **需要**，`MSDOS_FS=y` built-in |
| AF_ALG / KTLS | 不需要，全部删除 |
| 模块支持 | **接受 `CONFIG_MODULES=n`**，全部必要驱动 built-in |

最终结果：**0 个 .ko**，zImage 7.0MiB，vmlinux 18MiB。
